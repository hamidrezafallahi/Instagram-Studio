## M3.2 دارایی و نسخه‌بندی — passed (2026-11-17)
ساخته‌شده: `packages/media` (تشخیص نوع از محتوا، سنجش ابعاد PNG/JPEG/WebP، `AssetStore`)، migration `0003_assets.sql`، `packages/data/src/repos/assets.ts`، `packages/orchestration/src/assets.ts`، مسیرهای `listAssets`، `getAsset`، `uploadAsset` (بدنهٔ `application/octet-stream`) و `getAssetFile`، و `asset_ids` در `createContentRevision`.
آزمون: `tests/acceptance/m3-assets.test.ts` (۱۶ مورد: A04، A07، A17، نسخه‌بندی) و `packages/media/src/media.test.ts` (۷ مورد). کل مجموعه ۲۰۹ از ۲۰۹.
تفاوت با برنامه: جدول جدای asset_versions ساخته نشد (ردیف immutable + parent_asset_id)؛ checksum وارد هش نسخه نشد چون شناسهٔ ردیف immutable همان نقش را دارد، ولی ترتیب دارایی‌ها اکنون در هش هست (ADR-031). URL امضاشده به M5 موکول شد. مدت ویدئو تا M3.4 (ffprobe) خالی است. مسدودکردن انتشار دارایی با consent=missing در M5. UI بارگذاری در M3.5.

برنامهٔ اولیه:
- migration `0003_assets.sql`: جدول `assets` با workspace_id، brand_id، kind (image/video/subtitle/font/logo/source)، provenance (owner_upload/rendered/canva_import)، license، consent، checksum sha256، mime، width/height، duration_ms، language، storage_key، parent_id و version. RLS و قفل برند مثل جدول‌های دیگر.
- ذخیره: `STUDIO_HOME/assets/<brand_id>/<sha256>` (روی D). نشانی دانلود فقط از API با نشست مالک یا URL امضاشدهٔ کوتاه‌عمر؛ هیچ مسیر عمومی.
- upload: بررسی نوع فایل از محتوا (نه پسوند)، سقف حجم، نام‌فایل ایمن (A17).
- `content_revisions.asset_ids` به asset‌های واقعی اشاره می‌کند؛ hash نسخه شامل checksum دارایی‌هاست، پس تغییر تصویر approval را باطل می‌کند (A04).
- آزمون: نشت‌نکردن asset بین برندها (A07)، upload بد، تغییر asset ← approval نامعتبر.

## M3.3 رندر تصویر — passed (2026-11-17)
ساخته‌شده: `packages/media/src/render/` (مرورگر headless با CDP، parser اسلاید، قالب‌های پست/کاروسل/استوری/کاور ریلز، QA بصری)، فیلد اختیاری `visual` در BrandProfile و هویت بصری v1 در `config/brands/hamidreza-falahi/brand.json`، فونت در `config/fonts`، گردش‌کار `render_visuals` (`workflows/src/editorial/visual-render.ts`) و سرویس `packages/orchestration/src/visuals.ts`.
روش استفاده: run «ساخت تصویر» (`createRun` با `intent: render_visuals`؛ بدون `content_ids` همهٔ محتوای تصویری هفته که هنوز تصویر ندارند). هر اسلاید یک دارایی PNG با provenance=rendered؛ نسخهٔ تازهٔ محتوا همان متن و تصویرهای تازه را دارد.
آزمون: `tests/acceptance/m3-render.test.ts` (۸ مورد با Chrome واقعی) و `packages/media/src/render/render.test.ts` (۶ مورد). کل مجموعه ۲۲۳ از ۲۲۳. نمونهٔ رندر برند واقعی: [evidence/M3/render-sample/](evidence/M3/render-sample/).
تفاوت با برنامه: رندر (و تولید متن) به worker منتقل نشد؛ طبق ADR-022 درون‌فرایندی ماند (ADR-032). فونت mono سیستم به‌جای JetBrains Mono. تصویر واقعی (اسکرین‌شات، لوگو) هنوز در قالب جا داده نمی‌شود؛ قالب فقط متن است. دکمه‌ای در داشبورد برای این run در M3.5 اضافه می‌شود.
محدودیت: QA بصری جای بازبینی چشمی مالک را نمی‌گیرد. اگر Chrome/Edge نصب نباشد run با UNSUPPORTED_CAPABILITY شکست می‌خورد (آزموده).

برنامهٔ اولیه:
- روش پیشنهادی: قالب HTML/CSS → PNG با Chrome/Edge نصب‌شدهٔ همین دستگاه در حالت headless از طریق پروتکل DevTools (WebSocket داخلی Node؛ بدون بستهٔ npm تازه و بدون دانلود Chromium روی درایو پر C). مسیر مرورگر از تنظیم `STUDIO_BROWSER_PATH` یا جست‌وجوی خودکار؛ نبودش ← قابلیت `degraded` با پیام روشن.
- فونت فارسی: Vazirmatn (مجوز OFL)، embed در قالب و ثبت به‌عنوان asset نوع font با مجوز. دانلود فایل فونت با اجازهٔ مالک.
- قالب‌ها: پست 1080×1350، کاروسل (هر اسلاید یک PNG)، استوری 1080×1920، کاور ریلز؛ رنگ و لوگو از brand.json.
- visual QA در همان مرورگر: سرریز و بریدگی متن، خروج از safe area، اندازهٔ حداقل فونت، کنتراست؛ نتیجه در qa_result.
- اجرا در worker به‌صورت job (نه درون درخواست HTTP)؛ همین تغییر برای تولید متن هم انجام می‌شود.
