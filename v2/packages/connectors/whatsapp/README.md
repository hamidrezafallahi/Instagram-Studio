# WhatsApp کنترل مالک و پیام‌ها
از مسیر Business Platform رسمی یا provider دارای قابلیت اثبات‌شده؛ حساب شخصی را خودکار دارای Cloud API فرض نکنید.
فیلدهای فرم: WABA/phone_number_id در مسیر مستقیم، secret_ref، webhook config، templateهای مجاز، شمارهٔ مالک و scope برند.
pair با کد یک‌بارمصرف از داشبورد و تطبیق هویت کانال؛ داشتن نام مشابه مالک کافی نیست.
ورودی owner و customer دو نوع principal مجزا هستند؛ مشتری نمی‌تواند درخواست بودجه یا اجرای استودیو کند.
پنجرهٔ خدمات از last_user_message_at محاسبه؛ خارج پنجره از template تأییدشدهٔ مناسب در صورت دسترسی/رضایت استفاده شود؛ در غیر این صورت waiting_for_owner یا dashboard/Telegram.
هزینهٔ message با provider/کشور/دسته در billing بررسی شود؛ واتساپ همیشه رایگان فرض نشود.
برای پیام‌های درخواست شارژ از کانال رایگان در دسترس استفاده کنید تا درخواست شارژ خودش چرخهٔ پرداخت نسازد.
پذیرش: پیام خارج پنجرهٔ مجاز ارسال نشود؛ قطع دسترسی فقط همین کانال را متوقف کند؛ رخداد تکراری پاسخ تکراری نسازد.
منبع S07؛ کشور و شرایط حساب مالک هنگام onboarding بررسی شود.
