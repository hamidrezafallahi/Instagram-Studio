# سناریوهای پذیرش لازم
| شناسه | سناریو | انتظار قابل سنجش |
|---|---|---|
| A01 | ساخت چهار برند و برند پنجم سفارشی | بدون تغییر کد، داده/حساب/تقویم مستقل |
| A02 | demo بدون هیچ کلید | برنامه → draft → QA → fake publish با برچسب sample |
| A03 | دوبار کلیک اجرا | یک run منطقی با همان کلید |
| A04 | تغییر متن/تصویر پس از تأیید | approval قبلی نامعتبر |
| A05 | crash پس از پذیرش provider | reconcile یا unknown؛ بدون retry کور |
| A06 | webhook تکراری/خارج ترتیب | یک پاسخ و انتقال نسخهٔ درست |
| A07 | تعویض برند در UI/MCP | هیچ داده/asset/secret از برند قبلی نشت نکند |
| A08 | درخواست مدیر از DM مشتری | بدون اجرای فرمان مدیریتی |
| A09 | سهمیهٔ رایگان تمام شود | FundingRequest، مصرف پولی صفر بدون اختیار |
| A10 | دو job با بودجهٔ محدود | مجموع رزرو از سقف عبور نکند |
| A11 | شارژ دستی/منقضی‌شدن quote | تأیید اعتبار و بررسی دوباره قبل از resume |
| A12 | LinkedIn DM یا Trial بدون قابلیت | خروجی دستی و دلیل، نه موفقیت جعلی |
| A13 | قطع token/اینترنت | همان کانال متوقف؛ سایر برندها ادامه |
| A14 | خاموشی دستگاه و موعد گذشته | skip/reschedule طبق سیاست، بدون هجوم پست |
| A15 | pause هنگام انتشار | شروع جدید صفر؛ in-flight صادقانه گزارش شود |
| A16 | CMS staging و تغییر هم‌زمان انسان | draft/preview/rollback و conflict قابل مشاهده |
| A17 | webhook جعلی/SSRF/upload بد | رد قبل از اجرا و audit امن |
| A18 | local در برابر server | رفتار یکسان دامنه؛ محدودیت خاموشی روشن |
| A19 | export و حذف یک برند | عدم اثر بر برند دیگر؛ حذف مطابق retention |
| A20 | backup و restore | بازیابی با شمارش رکورد/asset، بدون اجرای مجدد کار کامل |
| A21 | سنجهٔ missing و ارز متفاوت | N/A و تفکیک ارز؛ بدون مجموع گمراه‌کننده |
| A22 | متن و ویدئوی فارسی | خوانایی، نیم‌فاصله، فونت و زیرنویس درست |
| A23 | free_only و fallback AI | به provider پولی switch نشود |
| A24 | حساب route مستقیم و واسط | فقط یک مسیر فعال؛ unknown مانع failover |
| A25 | Telegram/WhatsApp owner pairing | غریبه یا callback منقضی نتواند approve کند |
| A26 | MCP و dashboard یک intent | سیاست و audit همسان |
| A27 | سرویس تبلیغ بدون cap قابل اثبات | اجرای هزینه‌زای unattended غیرفعال |
| A28 | source قدیمی برای قیمت/موجودی | استعلام/ارجاع؛ بدون ادعای قطعی |

شرط تحویل production: A01–A28 متناسب با قابلیت فعال پاس شوند؛ موارد بیرونی مسدود صریحاً با manual flow آزموده شوند. برای هر capability فعال حداقل یک تست واقعی مجاز با رسید لازم است.
هدف کارایی پیشنهادی داخلی: ثبت command در صدک ۹۵ زیر ۲ ثانیه و dispatch سروری زیر ۶۰ ثانیه از موعد در بار ۴ برند/۱۰۰ job روزانه، به‌جز تأخیر provider؛ پس از benchmark تثبیت شود.
