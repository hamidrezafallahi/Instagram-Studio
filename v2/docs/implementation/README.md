# ترتیب پیاده‌سازی و تحویل
مراحل وابستگی دارند. هر مرحله با برش قابل استفاده و شواهد تست تحویل شود؛ همهٔ کانکتورها را هم‌زمان شروع نکنید.

| مرحله | کار | وابستگی | دروازهٔ پذیرش |
|---|---|---|---|
| M0 | تثبیت فرض‌ها، نسخه‌ها، قراردادها، threat model، انتخاب مسیر رایگان و capability register | ندارد | هر قابلیت وضعیت و مدرک/عدم قطعیت دارد |
| M1 | monorepo، auth مالک، DB، چند برند پویا، چهار pack، UI فارسی، fake connector | M0 | onboarding تا draft و گزارش sample بدون کلید اجرا شود |
| M2 | ActionIntent، approvals، budget/funding، outbox، worker، تقویم، pause و retry | M1 | double-click و crash انتشار تکراری نسازند |
| M3 | تولید متن، رندر تصویر/ویدئو، asset versioning و QA | M2 | خروجی فارسی قابل مشاهده و ویرایش، هزینه محدود |
| M4 | Telegram مالک و CMS نمونه در staging | M2,M3 | فرمان pairشده → draft → تأیید → انتشار آزمایشی مجاز → لینک واقعی |
| M5 | Instagram و LinkedIn publishing منتخب | M4 | اثبات هر قابلیت روی حساب مجاز؛ بقیه manual/blocked واقعی |
| M6 | inbox، CRM، WhatsApp و MCP | M4 | جداسازی owner/customer و مجوز یکسان از همهٔ ورودی‌ها |
| M7 | سئو، گزارش، ویرگول، بستهٔ تبلیغات و Canva | M5,M6 | audit سایت، تغییر قابل بازگشت، attribution و budget ledger |
| M8 | سخت‌سازی، backup/restore، deployment و راهنمای کامل | M7 | همهٔ سناریوهای پذیرش و آموزش مالک |

M4 نخستین نسخهٔ کاربردی داخلی است؛ M8 دامنهٔ کامل این طرح را پوشش می‌دهد. عدم دریافت مجوز LinkedIn/Meta را با «پشتیبانی خودکار کامل» جایگزین نکنید؛ سازوکار manual و چرایی محدودیت بخشی از تحویل است.
در M0 سازنده OpenAPI، JSON Schema، ERD و فهرست وابستگی‌ها را از متن قرارداد تولید کند؛ هیچ کد اجرایی در این بسته وجود ندارد.
در هر milestone: scope، فایل‌های تغییرکرده، فرمان‌های آزمون، نتیجه، محدودیت و مرحلهٔ بعد را ثبت کنید.
برآورد زمان پس از M0 و آزمون دسترسی‌ها ارائه شود؛ زمان تأیید سرویس بیرونی قابل تضمین نیست.
