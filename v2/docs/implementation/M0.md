# گزارش مرحلهٔ M0 — تثبیت فرض‌ها، نسخه‌ها و قراردادها
تاریخ: 2026-11-11 | محیط: Windows 11 x64، Node 26.4.0، pnpm 11.9.0 | وضعیت: passed

## دامنه
تثبیت فرض‌ها، قفل نسخه‌ها، تولید JSON Schema و OpenAPI و ERD از متن قرارداد، مدل تهدید، انتخاب مسیر رایگان و ثبت قابلیت‌ها.
دروازهٔ پذیرش: «هر قابلیت وضعیت و مدرک/عدم قطعیت دارد».

## تصمیم‌ها
ADR-013 تا ADR-023 در [DECISIONS.md](../architecture/DECISIONS.md). خلاصه:
- پوشهٔ `v2` ریشهٔ workspace؛ Node 26 LTS، TypeScript 7 برای type-check، اجرای مستقیم TS، آزمون با `node:test`.
- قرارداد code-first با zod؛ JSON Schema و OpenAPI تولیدی و هم‌خوان با API.
- PostgreSQL 18.6؛ در local بدون Docker با باینری توکار؛ RLS و نقش‌های جدا.
- دادهٔ اجرا و کلید اصلی خارج از مخزن (`STUDIO_HOME`).
- مسیر رایگان: API رسمی مستقیم پس از اثبات، وگرنه export دستی؛ Zernio/Postiz/Canva اختیاری.
- تولید بدون هزینه با provider قالبی محلی؛ بدون fallback پولی خودکار.

## اولین برش end-to-end (هدف M1)
راه‌اندازی مالک ← ساخت برند از pack ← اتصال نمونه و فهرست قابلیت واقعی ← «ساخت برنامهٔ هفته» (run با کلید یکتایی) ← «تولید پیش‌نویس» (brief ← متن ← QA ← آمادهٔ بازبینی، نسخهٔ immutable با hash) ← ویرایش = نسخهٔ تازه ← گزارش هفتگی sample با N/A و export.

## وضعیت قابلیت‌ها در پایان M0
از ۴۹ ردیف: ۲۲ `unverified`، ۱۶ `needs_access`، ۱۰ `manual_only`، ۱ `unsupported`، صفر `verified`.
هیچ حساب بیرونی متصل یا آزموده نشده است؛ مدرک‌های سند همان پژوهش S01 تا S21 بسته (2026-11-11) هستند و سازنده آن‌ها را دوباره نخوانده است. بازخوانی هر سند پیش از ساخت کانکتور همان مرحله انجام می‌شود.

## محدودیت‌ها
- دیسک C دستگاه ساخت تقریباً پر است (کمتر از ۱ گیگابایت آزاد). دادهٔ اجرا با `STUDIO_HOME=D:\ContentStudio` در `.env.local` به درایو D منتقل شد؛ `node_modules` (حدود ۴۵۰ مگابایت) روی C می‌ماند.
- Docker و ابزار کلاینت PostgreSQL (`pg_dump`) روی دستگاه نیست؛ روش پشتیبان‌گیری local در M8 تعیین می‌شود.
- برآورد زمان مرحله‌های M4 به بعد به دریافت دسترسی‌های بیرونی بستگی دارد و قابل تضمین نیست.
