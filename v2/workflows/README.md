# گردش‌کارهای محصول
تعریف workflow نسخه‌دار و پایدار؛ agent نام نقش تولید است، نه فرایند مستقل اجباری.
## W01 راه‌اندازی و برنامهٔ هفتگی
انتخاب brand → تکمیل BrandContext → بررسی منابع/حساب/بودجه → پیشنهاد اهداف و ظرفیت → تقویم نسخه‌دار → تأیید برنامه.
برنامه هدف، pillar، channel، format، مسئول، deadline، زمان انتشار، CTA و metric دارد.
## W02 تولید و انتشار
brief → تحقیق مستند → متن → رسانه → QA ادعا/لحن/فنی → preview → approval یا auto_scoped → schedule → publish → receipt → metrics.
approval برنامه به معنی تأیید متن نهایی نیست مگر سیاست صریح مالک همان محدوده را پوشش دهد.
## W03 پاسخ پیام
webhook → dedupe → تشخیص owner/customer → classification → دانش همان برند → draft → کنترل پنجره/اختیار/هزینه → ارسال یا handoff.
درخواست قیمت با منبع تازه؛ نبود اطلاعات، سؤال یا handoff؛ قیمت/تخفیف ساختگی ممنوع.
## W04 رشد ارتباط
موضوع‌های حرفه‌ای و منابع مجاز → فرصت تعامل با URL و دلیل ارتباط → متن اختصاصی → task دستی یا ارسال با قابلیت و مجوز → پیگیری outcome.
تعداد تعامل از ظرفیت و کیفیت تعیین شود، نه کامنت تکراری انبوه.
## W05 مقاله و سئو
audit → intent/keyword cluster → brief → مقاله با منابع/تصاویر → لینک داخلی → SEO QA → CMS draft → preview → publish → verify → پایش.
اصلاح فنی در ChangeSet جدا و قابل rollback.
## W06 تبلیغات و توزیع
هدف و landing → creative variants → quote/سهمیه → FundingRequest در صورت نیاز → approval → launch مجاز/بستهٔ دستی → نتیجه و توقف طبق سقف.
## W07 درخواست مالک
ورودی chat/MCP/پیام‌رسان → تعیین brand → intent → plan کوتاه و ابهام‌های ضروری → actionهای scopeدار → پیشرفت → گزارش نتیجه و موارد باقی‌مانده.
## W08 بازبینی هفتگی
تازه‌سازی سنجه → مقایسه با baseline → تحلیل با محدودیت داده → پیشنهاد آزمایش هفتهٔ بعد → تأیید تغییر برنامه.
پذیرش: هر گردش‌کار با دادهٔ نمونه و یک سناریوی شکست end-to-end نمایش داده شود.
