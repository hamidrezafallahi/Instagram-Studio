# Telegram کنترل مالک
اتصال با Bot API؛ token محرمانه، owner user_id و chat_id pairشده، webhook secret یا polling.
pair: مالک در داشبورد کد یک‌بارمصرف کوتاه‌عمر می‌سازد؛ همان فرد در chat خصوصی bot آن را وارد می‌کند؛ داشبورد تطبیق را تأیید می‌کند. username معیار هویت نیست.
فرمان‌ها: انتخاب برند، برنامهٔ هفته، تولید پیش‌نویس، وضعیت، گزارش، توقف، پاسخ ابهام و بررسی درخواست هزینه.
هر پیام مدیریتی context برند واضح دارد؛ اگر چند برند و مقصد مبهم است سؤال کند، حدس نزند.
دکمهٔ تأیید دارای intent/revision/TTL و نمایش خلاصه؛ forwarded message یا callback کاربر دیگر مجوز نیست.
polling برای local؛ فقط یک consumer برای bot token. در server webhook با HTTPS؛ polling و webhook هم‌زمان فعال نشوند.
فرمان stop مالک باید بدون نیاز به LLM قابل پردازش باشد. فایل ورودی محدود/scan و transcript صوتی اختیاری با بازبینی برای فرمان حساس.
پذیرش: webhook تکراری، کد pair منقضی، کاربر ناشناس و پاسخ به approval قدیمی رد؛ گفتگو برند درست را به‌روز کند.
